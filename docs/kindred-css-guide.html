Lesson 1 · tokens.css

Design tokens

Every color, spacing step, radius and font in Kindred is defined once, in tokens.css, as a CSS custom property. Components never write #cadf42. They write var(--lime).

Two facts make this powerful:

  • Custom properties inherit, just like color does. A value set on an element reaches every element inside it.
  • You can redefine one anywhere. The same name can hold different values in different parts of the page.

Dark mode is just the second fact. :root[data-theme="dark"] gives --paper and --ink new values, and every component follows without being edited.

Try it

Change a brand color. The tiles and buttons redraw because they read the variable. Only this box changes, because the new value is set on the box, not on :root.

CheckThe demo set --lime on the demo box. Why didn't the lime highlight in this page's title change too?
      
Custom properties only inherit downward. A value set on an element applies to that element and its descendants. The title sits outside the box, so it still inherits --lime from :root.

    
  


  
  

    
Lesson 2 · kindred.css 9–11, 30–33

    
Group themes with one attribute

    

      
Each rescue group picks one of four page colors. PublicSite puts that choice on the page root as data-gtheme="harbor". Four short rules then translate it into three generic variables.

      
    
        
  • --kd-g: the group's color (top bar, hero blob, group buttons)
    • 
        
  • --kd-g-on: the color that reads well on top of it
    • 
        
  • --kd-g2: the partner color behind the hero blob
    • 
      

      
Components only read the generic names, so they never know which theme is active. The -on suffix is a convention worth copying. Slate is the only dark theme, so --theme-slate-on is the light #f5f5f6, while the other three use navy.

Lesson 3 · kindred.css 86–126

    
BEM naming

    

      
Every class is Block__Element--Modifier, with a kd- prefix so nothing collides with outside styles.

    

    
    
      
  • BlockA standalone component. kd-card, kd-topbar, kd-sec
    • 
      
  • __ElementA part that only makes sense inside its block. kd-card__media, kd-card__name
    • 
      
  • --ModifierA variant of a block or element. kd-card--adoption, kd-btn--lime
    • 
    

    

      
The payoff is flat specificity. Almost every selector is one class, or two when a modifier styles its own elements (.kd-card--adoption .kd-card__name). Rules rarely fight, and the HTML tells you which CSS applies.

CheckIs kd-card__media--wide valid BEM? What about kd-card__media__img?
      
The first is fine: a modifier on an element. The second isn't. BEM never chains elements. A part nested deeper is still just an element of the block, so it would be kd-card__img. Kindred avoids the question by styling .kd-card__media img directly.

    
  


  
  

    
Lesson 4 · kindred.css 272–277 · PublicSite.tsx 151–160

    
Section anatomy

    

      
Every home page section is three nested layers:

      
    
        
  • <section class="kd-sec kd-sec--field-rescue"> is the band: full width, vertical padding, background color.
    • 
        
  • <div class="kd-wrap"> is the column: max 1240px, centered, 16px side gutter (40px on wide screens).
    • 
        
  • A layout class for the content: kd-grid, kd-rail, kd-cols, kd-prepgrid or kd-teamrail.
    • 
      

      
Keeping the band and column separate lets a background run edge to edge while the content lines up with every other section.

      
The band also carries scroll-margin-top: 120px. The top bar is sticky, so a jump link would park the heading at the very top of the screen, under the bar. Scroll margin tells the browser to stop short.

Jump with scroll margin off, and the heading lands under the bar. Turn it on and jump again. (Sizes are scaled down. The real margin is 120px.)

CheckThe field modifiers also set --notch. What is a variable on a section for, if the section never reads it?
      
The children read it. The paw badge draws a ring with box-shadow: 0 0 0 7px var(--notch, var(--paper)). Each section sets --notch to its own background, so the ring always matches what's behind the card and looks like a cut-out. Where no section sets it, the fallback --paper is used. This is lesson 1 again: redefine a variable on a subtree.

    
  


  
  

    
Lesson 5 · kindred.css 129

    
Why minmax(0, 1fr)

    

      
Kindred writes columns as repeat(2, minmax(0, 1fr)) instead of repeat(2, 1fr). It looks redundant. It isn't.

      
A 1fr track has a hidden minimum: it won't shrink below the min-content width of what's inside it. A card name with white-space: nowrap has a min-content width equal to the entire name. One long name forces its column wider and pushes the grid out of its container. minmax(0, 1fr) sets that minimum to zero, so both columns stay equal and the ellipsis can do its job.

    


    

      
Try it
The dashed line is the container. Switch between the two column definitions.

CheckFlex items have the same trap. What's the fix there, and where does Kindred use it?
      
min-width: 0 on the flex or grid child. Kindred uses it on .kd-topbar__brand so a long group name truncates instead of pushing the Contact button off screen, and on .kd-dash__body so wide dashboard content scrolls inside its panel.

    
  


  
  

    
Lesson 6 · app.css 4 · kindred.css 133–137

    
Container queries

    

      
A media query asks how wide the browser window is. A container query asks how wide a specific element is. Kindred turns #root into a container with one line, so every @container rule responds to the app's own width. The animal overlay declares its own container too.

      
This is what makes the dashboard preview work. The same public page renders inside a narrower panel and lays itself out for the space it actually has. A media query would see a wide window and wrongly pick the desktop layout.

      
Everything is mobile first: the base rule is the phone layout, and each @container (min-width: …) adds to it as space grows.

CheckThe hero name uses clamp(56px, 13cqi, 112px). What size is it in a 600px container? In a 400px one?
      
cqi is 1% of the container's inline size. At 600px, 13cqi is 78px, which sits between 56 and 112, so it's 78px. At 400px, 13cqi is 52px, below the 56px floor, so clamp holds it at 56px.

    
  


  
  

    
Lesson 7 · kindred.css 130–135 · PublicSite.tsx 155

    
Rail to grid

    

      
On phones the Rescue Gallery is a swipe carousel. From 720px it's a grid. Same element, same cards; only the CSS changes.

      
    
        
  • The rail: grid-auto-flow: column puts every card in one row, and grid-auto-columns: 72% makes each one 72% wide so the next card peeks in, hinting that you can swipe. scroll-snap-type: x mandatory makes a swipe land on a card.
    • 
        
  • The bleed: margin: 0 -16px pulls the rail out past .kd-wrap's gutter so cards slide off the true screen edge. padding: 0 16px pushes the first card back into line, and scroll-margin-left: 16px makes snapping respect that.
    • 
        
  • The handoff: React passes the card count as --n and a column cap as --max. With two rescues you get two columns capped at 360px rather than two cards stretched across a four-column grid.
    • 
      

    


    

      
Try it
Below 720px, swipe the cards (or shift + scroll). Turn off snapping to feel the difference. Then widen past 720 and change the count.

      

        
        
        
        
      

      

        

      

      

    


    

    


    
CheckWhy does the rail hide its scrollbar and set overscroll-behavior-x: contain?
      
The peeking card already tells people they can swipe, so a scrollbar is visual noise on phones. overscroll-behavior-x: contain stops a swipe that reaches the end of the rail from carrying over into browser back/forward gestures or scrolling the page sideways.

    
  


  
  

    
Lesson 8 · kindred.css 39–67

    
Hover, press and color-mix

    

      
Hover colors are mixed, not picked. color-mix(in oklab, var(--lime) 86%, var(--navy)) is 86% lime with 14% navy. It's computed from tokens, so hover states follow when a token changes, and there are no extra hex values to maintain. Mixing in oklab keeps the result from going muddy.

      
Hover only exists for mice. Every hover rule sits inside @media (hover: hover) and (pointer: fine). On a phone, a tap leaves :hover stuck on until you tap somewhere else. The query keeps hover styles to devices that really hover.

      
Press feedback works everywhere. :active { transform: scale(0.97) } is outside the query, so taps get it. Its transition uses --kd-dur-press (140ms) while colors use --kd-dur-ui (200ms). A press should feel instant; a color can ease.

CheckWhy does the secondary button draw its outline with box-shadow: inset 0 0 0 1.5px instead of border?
      
A border adds to the element's size, so an outlined button would be 3px taller than the filled buttons beside it unless you compensated with padding. An inset shadow draws inside the box without affecting layout. It uses currentColor, so it always matches the text.

    
  


  
  

    
Lesson 9 · motion.tsx 9–24 · kindred.css 706–729

    
Scroll reveal and stagger

    

      
JavaScript decides when; CSS decides how. useReveal() watches every [data-reveal] element with an IntersectionObserver and adds data-shown once it's 10% in view. That is all the JavaScript does.

      
The CSS hides the children until data-shown appears, then animates them in. The stagger comes from --i: :nth-child(2) sets --i: 1, :nth-child(3) sets --i: 2, and so on. Each child's delay is calc(var(--i) * 80ms).

      
The fill mode backwards matters. During its delay, each card is held at the from keyframe (invisible), so cards don't flash on and then vanish before their turn.

    


    

      
Try it
Replay the reveal, change the step between cards, or simulate reduced motion.

      

        
        
        
      

      

        

      

      

    


    

    


    
CheckuseReveal's useEffect has no dependency array, so it runs after every render. Isn't that wasteful?
      
It's deliberate. Sections can appear later, after data loads or a filter changes, and they need observing too. The query only picks up elements without data-shown, so cards that already revealed are skipped and each run stays cheap.

    
  


  
  

    
Lesson 10 · kindred.css 579–591, 727, 731

    
The tag pile

    

      
The footer's section tags look hand-tossed, but there's no randomness. :nth-child(5n+1) through :nth-child(5n) give five tags five angles through --r, then the pattern repeats. margin-right: -6px lets neighbors overlap a little, which sells the pile.

      
Keeping the angle in a variable pays off twice. The resting transform is rotate(var(--r)), and the drop-in keyframe starts from rotate(calc(var(--r) - 16deg)). One keyframe serves every tag, and each swings into its own angle.

      
The bounce is the easing: cubic-bezier(0.34, 1.56, 0.64, 1). A second y value above 1 overshoots the end, then settles back.

    


    

      
Try it
Add tags to watch the 5-step pattern repeat. Replay with and without the overshoot. Hover a tag to straighten it.

      

        
        
        
        
      

      

      

    


    


    
CheckThe 9th tag gets --r: 8deg. Which rule matches it, and why?
      
:nth-child(5n+4). With n = 1, 5n+4 = 9. The other rules give 6 (5n+1), 7 (5n+2), 8 (5n+3) and 10 (5n). Every pattern of five restarts the cycle.

    
  


  
  

    
Lesson 11 · kindred.css 224–236

    
Marquee bands

    

      
The endless scroll is a trick with two copies. The track holds the list twice, side by side, and is width: max-content so it's as long as both. The animation moves it by translateX(-50%): exactly one copy's width. At that moment copy 2 sits exactly where copy 1 started, so the loop restarts with no visible jump.

      
Band B runs in reverse at 72s against band A's 60s, so the two never fall into step. Hovering pauses both with animation-play-state. Each band is 112% wide with margin-left: -6% so the tilted ends never show a gap at the sides.

    


    

      
Try it
Reveal the two copies, then speed it up and watch copy 2 take copy 1's place. Hover to pause.

      

        
        
        
      

      

        

          

          

        

      

      

    


    


    
CheckWhat goes wrong if the two copies aren't identical in width?
      
-50% is half the track, which equals one copy only when both copies match. If they differ, the track is in the wrong spot when the loop restarts and the text visibly jumps.

    
  


  
  

    
Lesson 12 · kindred.css 733–737

    
Scroll-driven animation

    

      
The public top bar gains a shadow as you scroll, with no JavaScript. animation-timeline: scroll(root block) ties the animation's progress to the page's scroll position instead of to time. animation-range: 0 140px maps 0px scrolled to the start and 140px to the end, so the shadow fades in over the first 140px.

      
It's wrapped in @supports (animation-timeline: scroll()). Browsers without support skip the block and keep a flat bar, which is fine. That's the pattern for any enhancement where the fallback is acceptable.

    


    

      
Try it
Scroll inside the box. Turn on "exaggerate" to make the effect obvious. This demo uses scroll(nearest block) because it scrolls a box, not the page.

CheckWhy linear easing here, when everything else uses --kd-ease-out?
      
Progress already comes from your finger or wheel. A curve would make the shadow change unevenly while you scroll evenly. Linear maps scroll distance straight to shadow strength. The both fill keeps the start state before scrolling and the end state after 140px.

    
  


  
  

    
Lesson 13 · kindred.css 739–746 · app.css 6, 13–14

    
Safety nets

    

      
Three rules protect people who need them. They're easy to forget and expensive to add later.

      
    
        
  • Reduced motion, two layers. Decorative animation sits inside @media (prefers-reduced-motion: no-preference), so it only runs for people who haven't asked for less motion. As a backstop, a reduce block at the end shrinks every animation to 1ms and limits transitions to opacity and color.
    • 
        
  • Visible keyboard focus. :focus-visible draws a 2px outline for keyboard users only. A mouse click doesn't trigger it.
    • 
        
  • A skip link. .kd-skip sits off screen at top: -48px and slides to top: 12px on focus, so keyboard users can jump past the navigation.
    • 
      

    


    

      
Try it
Click "Start here", then press Tab once. The skip link appears. Press Enter to use it.

CheckWhy does the backstop use animation-duration: 1ms instead of animation: none?
      
With 1ms the animation still technically runs. Elements land on their final keyframe state, and any code listening for animationend still gets the event. With none, neither happens, which can leave things half-hidden or stuck waiting.
